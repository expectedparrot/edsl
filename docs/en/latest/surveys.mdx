A `Survey` is your research instrument: it groups questions and defines their order, branching, and dependencies. It can collect a rating and explanation, apply several codes to a document, or guide a longer interview. The survey holds the questions and rules; completed answers belong to a [Results](/en/latest/results) object.

You can reuse the same survey with different scenarios, agent profiles, or models, or publish it for human participants. These choices determine who answers and what material they see without requiring you to rewrite the instrument.

For [data labeling](/en/latest/guides/data_labeling), a survey might ask about each item's topic, sentiment, and urgency; the answers become its labels. An exploratory survey can also help you discover useful categories before you construct a structured labeling survey.

## Assemble questions

Construct questions before passing them to `Survey([...])`. Each question must have a unique name. See [Questions](/en/latest/questions) for choosing types; the survey controls how those questions work together.

## Logic, piping, and memory

This example stops after the first question for respondents who have not used a feature. Otherwise, it pipes their description into a follow-up and supplies the earlier answer as memory. Constructing the survey makes no model calls.

<SurveyLogicExample />

A stop rule is evaluated after its question. A skip rule can bypass an individual question before it is asked. Write expressions using named answers, and test each possible route. Piping inserts an answer in question text; memory includes a previous question and answer in the context supplied to the model.

See [Survey logic and piping](/en/latest/guides/survey_logic) for testing routes and [Survey messages](/en/latest/survey_messages) for instructions shown between questions.

## Prepare a run

Combine a survey with scenarios, agents, and models using `by()` to construct a [Jobs](/en/latest/jobs) object. For example, `survey.by(messages).by(model)` prepares one interview per message scenario; calling `.run()` collects the answers. Use `survey.run()` when you want to ask it once with the default model and no custom profiles or scenarios. See [Model access](/en/latest/api_keys) for connecting a model.

For human participants, use [Human studies](/en/latest/guides/human_studies). A web survey requires an Expected Parrot account.

## Edit and inspect a survey

Access a question by name with `survey.get("feedback")` or `survey["feedback"]`. Use `survey.question_names` to inspect the order. To revise wording while keeping the original survey:

```python
from edsl import QuestionFreeText, Survey

survey = Survey([
    QuestionFreeText(question_name="feedback", question_text="What should improve?"),
])
revised = survey.with_edited_question(
    "feedback", {"question_text": "What one change would help you most?"}
)
renamed = revised.with_renamed_question("feedback", "priority")
renamed.codebook()
```

`with_renamed_question()` also updates references to the question. `survey.rename({"old_name": "new_name", ...})` renames multiple questions. `codebook()` returns a dictionary of names and question text.

| Task | Method and behavior |
| --- | --- |
| Move or remove a question | `survey.move_question("feedback", new_index=0)` and `survey.delete_question("feedback")` modify the survey. |
| Build a smaller questionnaire | `survey.subset("q1", "q2")` keeps those questions; `survey.drop("q3")` removes named questions. Both return a new Survey. Reapply and check routing, instructions, and memory for the new instrument. |
| Inspect question definitions as rows | `survey.to_dataset()` or `survey.to_scenario_list()`; `survey.select("question_name", "question_text")` selects columns of a table, not a smaller Survey. |
| Inspect routing | `survey.show_rules()` displays rules; `survey.show_flow()` renders a flow diagram and may require Graphviz. |
| Export for review | `survey.to_markdown()` returns text; `survey.to_docx("survey.docx")` and `survey.to_html(filename="survey.html")` return FileStore objects and write the files. |
| Prepare execution without added components | `survey.to_jobs()` returns Jobs. `survey.run(...)` and `await survey.run_async(...)` execute the survey with run options. |

For grouped human survey pages, use `survey.add_question_group(start_question, end_question, group_name)`; `get_question_group(question)` reports a question's group. See [Question groups](/en/latest/humanize_groups) for grouping constraints.

## Common methods

| Call | Arguments and result |
| --- | --- |
| `Survey([question, ...])` | Create a survey with questions in the supplied order. |
| `survey.add_question(question, index=None)` | Insert a question at the given index, or append it when the index is omitted; return the survey. |
| `survey.add_skip_rule(question, expression)` | Skip the named question when the expression is true before it is asked. |
| `survey.add_stop_rule(question, expression)` | End the survey when the expression is true after the named question. |
| `survey.add_targeted_memory(focal_question, prior_question)` | Include a prior question and answer in the focal question's model context. |
| `survey.by(agents).by(scenarios).by(model)` | Return a Jobs object configured with those study components. |
| `survey.save("survey.ep")` / `Survey.load("survey.ep")` | Save and restore the survey definition locally. |

Rule and memory methods accept question names or question objects. They return the survey so you can chain calls. For example, this constructs a two-question survey with a stop rule:

```python
from edsl import QuestionYesNo, QuestionFreeText, Survey

used = QuestionYesNo(question_name="used", question_text="Have you used this service?")
feedback = QuestionFreeText(question_name="feedback", question_text="What should improve?")
survey = Survey([used, feedback]).add_stop_rule("used", "{{ used.answer }} == 'No'")
```

For model runs, call `run()` on the configured job; see [Jobs](/en/latest/jobs#execution-options) for execution options. For a participant link, follow [Human surveys](/en/latest/humanize).
