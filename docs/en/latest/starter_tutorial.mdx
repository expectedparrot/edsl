This tutorial takes you from a single feedback question to classifying several messages and exporting the answers. You will see how questions, scenarios, models, and results fit together. It begins with a fixed local test response, then shows how to choose a language model for the same workflow.

## Install EDSL

Follow [Installation](/en/latest/installation) for supported Python versions and environment setup:

```bash
pip install edsl
```

Run the code in a notebook or Python script. The [CLI Guide](/en/latest/cli) provides an equivalent command line workflow.

## Log in to Expected Parrot

To use Expected Parrot's model access from a notebook, run:

```python
from edsl import login

login()
```

Follow the sign-in link in the cell output. EDSL retrieves and stores your API key automatically. For login options or direct provider access, see [Model access and API keys](/en/latest/api_keys).

## Choose a language model

Inspect the current model catalog with `Model.available()` or `ep models --text`. Select a model appropriate for the task and review [costs](/en/latest/costs).

Calling `Model()` without a name selects your configured default model. You can inspect its name and parameters:

```python
from edsl import Model

model = Model()
{"model": model.model, "parameters": model.parameters}
# In a script, wrap this expression in print() to display it.
```

To choose a specific model instead, pass its name to `Model()` and its provider's service name as `service_name`. Replace both placeholders below with the corresponding identifiers from the catalog:

```python
model = Model("MODEL_NAME", service_name="SERVICE_NAME")
```

Model names and availability change, so use the current catalog values. You can also pass parameters supported by your chosen model as keyword arguments; see [Language models](/en/latest/language_models) for configuration details.

Once you have chosen either the default or a specific model, apply it to the job and run the survey. This makes model calls and may incur usage costs:

```python
results = job.by(model).run()
```

Expected output is three completed interview records, each with an `answer.sentiment` value from the allowed options. Actual labels depend on the model and inputs; inspect errors and completion counts before analysis.

## Inspect and export responses

```python
table = results.select("scenario.record_id", "scenario.feedback", "answer.sentiment")
# Display in a notebook: put table on the last line of a cell.
# Display in a script: table.print()
# Convert to pandas when you need DataFrame operations.
frame = table.to_pandas()
table.to_csv("feedback_labels.csv")
```

Keep the record identifier beside each answer so you can join classifications to source data or human labels. See [Results](/en/latest/results) and [Dataset](/en/latest/dataset) for filtering, comparison, and export.
