title: "Human surveys"
description: "EDSL comes with built-in methods for generating web versions of your surveys and collecting and analyzing responses from humans."
---

`humanize()` turns an EDSL Survey into a web questionnaire that people can complete. It preserves the questions and survey logic while adding a respondent interface, an administration page, and response collection. Start with [Human studies](/en/latest/guides/human_studies) for a short end-to-end example; use this page to configure scenarios, respondent lists, and data retrieval.

<Note>
This page covers code methods for launching surveys, gathering human responses, and analyzing results. For interactive survey building, see [Survey Builder](/en/latest/survey_builder). For Prolific recruitment, see [Prolific studies](/en/latest/prolific). For email notifications and scheduled reminders, see [Survey notifications](/en/latest/humanize_notifications). To let AI agents take a survey, see [AI agent access](/en/latest/humanize_agent_access).
</Note>

## How it works

<Steps>
<Step>
    **Create** [Surveys](/en/latest/surveys) with desired types of [Questions](/en/latest/questions).
</Step>
<Step>
    **Humanize** the survey to generate a web-hosted version on Expected Parrot with a respondent link and an admin dashboard.
</Step>
<Step>
    **Share** the respondent link with human participants (or recruit via [Prolific](/en/latest/prolific)).
</Step>
<Step>
    **Collect** responses back as a standard EDSL `Results` object.
</Step>
<Step>
    **Analyze** your human results alongside any LLM results.
</Step>
</Steps>

## Basic usage

The example collects three measures of workplace experience: work-from-home frequency, satisfaction, and a suggested improvement. After defining the questions, `.humanize()` publishes them using your [Expected Parrot account](/en/latest/api_keys#log-in-from-a-notebook).

```python
from edsl import Survey, QuestionMultipleChoice, QuestionFreeText, QuestionLinearScale

q1 = QuestionMultipleChoice(
    question_name="frequency",
    question_text="How often do you work from home?",
    question_options=["Never", "1-2 days a week", "3-4 days a week", "Every day"],
)
q2 = QuestionLinearScale(
    question_name="satisfaction",
    question_text="How satisfied are you with your current work arrangement?",
    question_options=[1, 2, 3, 4, 5],
    option_labels={1: "Very dissatisfied", 5: "Very satisfied"},
)
q3 = QuestionFreeText(
    question_name="improvement",
    question_text="What one change would most improve your day-to-day work experience?",
)

survey = Survey([q1, q2, q3])

info = survey.humanize(
    human_survey_name="Workplace Experience Survey",
    survey_description="A short survey about remote and in-office work preferences.",
    survey_visibility="unlisted",
)

info  # Contains the respondent link, admin link, and collection UUID.
```

### `.humanize()` parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `human_survey_name` | str | `"New survey"` | Display name on Expected Parrot |
| `survey_description` | str \| None | None | Optional description |
| `survey_alias` | str \| None | None | URL-friendly alias |
| `survey_visibility` | str | `"private"` | `"private"`, `"public"`, or `"unlisted"` |
| `humanize_schema` | dict \| None | None | Controls question styling and optionality — see [Humanize schema](/en/latest/humanize_schema) |

### Return value

`survey.humanize()` returns a `Scenario` (dict-like) with these keys:

| Key | Description |
|-----|-------------|
| `uuid` | Human survey UUID — needed to fetch responses later |
| `respondent_url` | Public link for respondents |
| `admin_url` | Admin dashboard link |
| `name` | Survey name |
| `n_responses` | Response count (0 at creation) |
| `survey_uuid` | UUID of the pushed survey object |
| `scenario_list_uuid` | UUID of the pushed scenario list (if any) |
| `asset_substitutions` | Old asset uuid → new one, when the schema named assets that were copied into your library. Empty when nothing was copied |

**Save the `uuid`** — you need it to retrieve responses.

## Previewing before deployment

Use `.preview()` to get a preview URL without creating a live survey:

```python
preview_url = survey.preview()
# print() also shows output in scripts. In a notebook, you can instead
# put the value you want to inspect on the last line of a cell.
print(preview_url)

# With schema customization
schema = {"questions": {"improvement": {"optional": True}}}
preview_url = survey.preview(humanize_schema=schema)
```

## Present questions in groups

To request one group per page, define contiguous question groups on the survey and pass `humanize_schema={"survey": {"presentation": "group"}}` to `.humanize()`. See [Grouped surveys](/en/latest/humanize_groups) for a complete example, branching behavior, and availability requirements.

## Add your logo

To show your own logo above the questions, upload the image once and reference it from the humanize schema:

```python
from edsl import Coop

logo = Coop().upload_human_survey_asset("lab_logo.png")

survey.humanize(
    human_survey_name="Customer feedback",
    humanize_schema={
        "survey": {
            "branding": {
                "logo": {
                    "source": {"type": "asset", "asset_uuid": logo.uuid},
                    "alt": "Acme Research logo",
                }
            }
        }
    },
)
```

Uploading the same file again returns the asset you already have, so re-running a script does not fill your library with copies.

`Coop().list_human_survey_assets(page=1, page_size=20)` lists a page of image-library metadata. `Coop().get_human_survey_asset(asset_uuid)` returns a `HumanSurveyAsset`; its `download("logo.png")` method saves the image locally. `Coop().delete_human_survey_asset(asset_uuid)` removes an asset when you intend to delete it.

From the CLI, upload once and apply it to a survey that already exists:

```bash
ep humanize assets upload lab_logo.png
ep humanize schema set <human-survey-uuid> --logo-asset <asset-uuid> --logo-alt "Acme Research logo"
```

Or do both in one step:

```bash
ep humanize schema set <human-survey-uuid> --logo-file lab_logo.png --logo-alt "Acme Research logo"
```

See [Humanize schema](/en/latest/humanize_schema) for the `branding` fields, and [Custom CSS](/en/latest/custom_css) for resizing the logo or putting it on a colored banner.

## With scenarios

When using scenarios, call `.humanize()` on a `Jobs` object (not directly on the survey). You must specify a `scenario_list_method`.

Use scenarios for stimulus material or treatment conditions. This example assigns each respondent one of three policy descriptions and asks for a support rating and its reason. Random assignment can select the same policy for several respondents:

```python
from edsl import Survey, QuestionFreeText, QuestionLinearScale, Scenario, ScenarioList

scenarios = ScenarioList([
    Scenario({"policy": "Four-day workweek with no change in pay"}),
    Scenario({"policy": "Flexible start times between 7am and 11am"}),
    Scenario({"policy": "Monthly remote-work stipend of $100"}),
])

q1 = QuestionLinearScale(
    question_name="support",
    question_text="How much do you support this policy: '{{ scenario.policy }}'?",
    question_options=[1, 2, 3, 4, 5],
    option_labels={1: "Strongly oppose", 5: "Strongly support"},
)
q2 = QuestionFreeText(
    question_name="reasoning",
    question_text="What is the main reason for your rating?",
)

survey = Survey([q1, q2])

info = survey.by(scenarios).humanize(
    human_survey_name="Workplace Policy Reactions",
    scenario_list_method="randomize",
)
```

### Scenario list methods

| Method | Behavior |
|--------|----------|
| `"randomize"` | Each respondent gets a random scenario (with replacement) |
| `"ordered"` | Scenarios are assigned sequentially to respondents |
| `"loop"` | Survey is expanded — every question is repeated for every scenario |
| `"single_scenario"` | Exactly one scenario is used for all respondents (list must have length 1) |

**Rules:**
- If you attach scenarios, you **must** specify `scenario_list_method`.
- If you specify a method, you **must** attach scenarios.
- Do not attach language models to a human-survey job. An AgentList can supply participant metadata and delivery addresses, as described below; it does not generate simulated responses.

## With agent lists (for email notifications)

Attach an `AgentList` via `.by()` to associate respondents with email addresses. Pass a `DeliveryMap` to tell Coop which agent trait holds the email address.

```python
from edsl import Survey, Agent, AgentList
from edsl.coop.coop_humanize_notifications import ChannelConfig, DeliveryMap

agents = AgentList([
    Agent(traits={"name": "Jordan", "email": "jordan@example.com"}),
    Agent(traits={"name": "Taylor", "email": "taylor@example.com"}),
    Agent(traits={"name": "Morgan", "email": "morgan@example.com"}),
])

info = survey.by(agents).humanize(
    human_survey_name="Panel Study — Wave 1",
    agent_list_description="Recruited panel participants",
    delivery_map=DeliveryMap(email=ChannelConfig(col_name="email")),
)
```

`col_name` must match the trait key that holds each respondent's email address. Once deployed, use [Survey notifications](/en/latest/humanize_notifications) to send invitations, schedule reminders, and track delivery status.

## Retrieving responses

```python
from edsl import Coop

coop = Coop()

results = coop.get_human_survey_responses("your-human-survey-uuid")
# In a notebook, the last expression displays the selected table.
# In a script, append .print() to display it.
results.select("answer.frequency", "answer.satisfaction", "answer.improvement")
```

### What the results contain

Each completed response is one result, oldest first. Retrieving data reads the recorded answers; it does not rerun the questionnaire. Skipped questions stay skipped. Column names match the responses table on the survey's page. Select `scenario.*` alongside answers when you need to compare the material or condition each respondent received.

| Field | Description |
|-------|-------------|
| `answer.{question}`, `comment.{question}_comment` | The respondent's answer and comment. Empty for a question they didn't see. |
| `agent.response_uuid`, `agent.agent_name` | The response's ID. |
| `agent.respondent_uuid`, `agent.agent_index` | The respondent's ID and position in the attached agent list. Empty without an agent list. |
| `agent.{trait}` | The traits of the respondent's agent, when an agent list is attached. |
| `raw_model_response.{question}_started_at`, `_answered_at` | When the respondent reached and answered the question. |
| `raw_model_response.{question}_question_presented` | `False` if survey logic skipped the question, so a skipped question can be told from one left blank. |
| `question_options.{question}_question_options` | The options as the respondent saw them, after piping and any randomized order. |
| `agent.external_platform`, `agent.prolific_*` | The Prolific submission, study and participant IDs, when any response came through Prolific. |

Fields that show how a response was collected, such as `agent.collection_interface`, are listed under [AI agent access](/en/latest/humanize_agent_access#in-results). The `model.*` columns describe a placeholder model: a human response has no model, but every result records one.

To get only some responses, pass `started_after` and/or `started_before` (inclusive; a response is "started" when the respondent opened the survey).

### Checking response count

```python
status = coop.get_human_survey("your-human-survey-uuid")
print(f"Responses received: {status['n_responses']}")
```

### Find surveys and inspect respondent progress

Use Python pagination when retrieving account records:

```python
surveys = coop.list_human_surveys(search_query="Workplace", page=1, page_size=20)
respondents = coop.get_human_survey_respondents(
    "your-human-survey-uuid", page=1, page_size=50,
)
respondents
```

These calls return response dictionaries with records and pagination information; inspect the returned metadata before requesting another page. `coop.get_human_survey_agent_list(uuid)` retrieves the attached respondent list configuration. To change its delivery mapping or participation settings, use `coop.patch_human_survey_agent_list(...)`; see [notifications](/en/latest/humanize_notifications) and [AI agent access](/en/latest/humanize_agent_access).

For events logged by a survey's [custom JavaScript](/en/latest/custom_javascript), `coop.get_human_survey_events(uuid, limit=200)` retrieves a batch. While `has_more` is true, pass the returned `next_cursor` as `after` to continue, or use `coop.get_all_human_survey_events(uuid)` to collect all batches. `coop.count_human_survey_events(uuid)` counts those events. Preview events are included and marked `is_preview`; exclude them from participant analyses. Use `get_human_survey_responses()` for answer data.

### Working with file upload responses

If your survey includes a `QuestionFileUpload` question, each response's answer for that question is a list of file-info dicts. Use `FileStore.from_file_upload_answer` (single file) or `FileStoreList.from_file_upload_answers` (all files at once) to download and wrap them:

```python
from edsl import Coop
from edsl.scenarios import FileStore, FileStoreList

coop = Coop()

results = coop.get_human_survey_responses("your-human-survey-uuid")

# Each answer is a list of uploaded file dicts
uploaded_files = results[0]["answer"]["my_upload_question"]

# Download all files as a FileStoreList
fsl = FileStoreList.from_file_upload_answers(uploaded_files)

# Or download a single file
fs = FileStore.from_file_upload_answer(uploaded_files[0])
```

The returned `FileStore` and `FileStoreList` objects behave like any other — you can inspect, filter, or pass them into further EDSL workflows.

## QR code

Generate a QR code for the respondent link using `get_human_survey_qr_code()`. Requires the `qrcode` library (`pip install "edsl[full]"` or `pip install "qrcode[pil]"`).

```python
from edsl import Coop

coop = Coop()

qr = coop.get_human_survey_qr_code("your-human-survey-uuid")
qr.save("qr_code.png")  # save to file
```

From the CLI, generate a QR code for the shared respondent URL:

```bash
ep humanize qr <human-survey-uuid> --output survey-qr.png
```

When the human survey has an attached agent list, export the roster together
with each respondent's personal link:

```python
links = coop.get_human_survey_respondent_links(
    "your-human-survey-uuid", save_path="respondent-links.csv",
)
# links is a Dataset; the CSV contains the personal respondent URLs.
```

The CLI alternative is:

```bash
ep humanize links <human-survey-uuid> --output respondent-links.csv
```

Add `--qr-dir` to generate one personal QR code per respondent and record each
PNG path in the CSV:

```bash
ep humanize links <human-survey-uuid> \
  --output respondent-links.csv \
  --qr-dir respondent-qr
```

Personal links and QR codes contain access tokens and act as bearer credentials.
Store the export securely and share each link or code only with its intended
respondent. The CLI returns only file metadata on stdout, never the links.
