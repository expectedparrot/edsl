A shared activity poll, from first principles

A runnable introduction to EDSL’s new shared-state syntax: define a small state machine, give it scopes, read it explicitly inside a Survey, and write an answer back atomically.

1. Mental model2. Define the machine 3. Create personas4. Choose a scope 5. Put state in a Survey6. Run locally 7. Inspect the audit trail8. Complete program

1. The mental model

Ordinary EDSL questions produce independent answers. Shared state lets one interview observe or change information that other interviews can also use. Four concepts are kept separate:

Machine

The data, commands, and public view for one kind of shared object.

SharedState

A named collection of machines—for example, a machine named poll.

SharedStateMap

A collection of independent state spaces selected by structured scope keys.

Survey steps

Explicit moments when an interview reads state or submits a write.

Resolve scope
Read snapshot
Render question
Collect answer
Apply write
Storage is deliberately absent here. The machine, state map, and Survey contain no filename or database connection. Local execution creates a local binding; a future Coopr execution can bind the same serialized definitions to PostgreSQL.

2. Define the machine

The poll stores a dictionary from voter name to activity. Its only command is vote. Calling it replaces that voter’s existing choice or inserts a first choice.

def activity_poll() -> Machine:
    return Machine(
        name="ActivityPoll",
        constants={"activities": ACTIVITIES},
        fields={
            "votes": state_field(
                T.map(T.text(), T.choice(ACTIVITIES)),
                {},
            )
        },
        commands={
            "vote": Command(
                inputs={
                    "voter": T.text(),
                    "activity": T.choice(ACTIVITIES),
                },
                effects=(
                    put("votes", input_("voter"), input_("activity")),
                ),
            )
        },
        view={
            "votes": field("votes"),
            "counts": reduce_("count_by", field("votes").values()),
        },
    )
SyntaxMeaning
state_field(type, initial)Declare durable machine data and its initial value.
T.map(...), T.text(), T.choice(...)Serializable runtime types. Invalid command inputs are rejected.
input_("voter")A symbolic reference to a command argument—not its value yet.
field("votes")A symbolic reference to the current machine field.
put(...)An atomic dictionary update performed by the execution host.
view={...}The public snapshot exposed by poll.read(). Derived counts need not be stored.

These expressions are data, not arbitrary Python callbacks. That is what makes the definition inspectable, serializable, type-checkable, and eventually safe to execute on another host.

3. Create strong, heterogeneous personas

Sixteen agents are balanced across four preferred activities, then shuffled. They receive separate preference-strength and conformity traits, so liking an activity and wanting to join the group are not conflated.

TRAITS_TEMPLATE = """You are a member of a group choosing a weekend activity.
Your preferred activity is {{ preferred_activity }}.
Your preference strength is {{ preference_strength }} on a 0-to-1 scale:
0 means you have no attachment to it; 1 means you feel extremely strongly.
Your conformity is {{ conformity }} on a 0-to-1 scale: 0 means you ignore what
other people chose; 1 means you strongly prefer joining the emerging consensus.
Vote as this person would, trading off personal preference against the votes you
can currently see. When there is no clear group preference, favor your own.
"""

return AgentList(
    agents,
    traits_presentation_template=TRAITS_TEMPLATE,
)

The braces here are Jinja references interpreted when the agent prompt is built. Operational metadata such as family_id can remain a trait without appearing in this presentation.

4. Create state spaces and select one

spaces = SharedStateMap(
    SharedState(poll=activity_poll()),
    state_id="weekend-activity-poll",
)

family = spaces.by(current.agent.family_id)

SharedState(poll=...) gives the machine the local name poll. A state could eventually contain other named machines too, but this tutorial needs only one.

SharedStateMap is the container of scoped states. The expression current.agent.family_id is resolved separately for every interview. Agents with the same value share one poll; agents with different values use independent polls.

current is a typed, serializable reference. It is not a Jinja string and it is not evaluated while the Survey is being authored. At execution, the host resolves it from the current interview context.

The stable state_id identifies the durable state resource. The scope key identifies an entry within it:

state resource:  "weekend-activity-poll"
scope key:       "weekend-group"
machine:         "poll"

5. Put reads and writes inside the Survey

activity = QuestionMultipleChoice(
    question_name="activity",
    question_text=(
        "Current votes are {{ shared_state.poll.votes }}. "
        "Which activity should the group choose?"
    ),
    question_options=list(ACTIVITIES),
)

survey = Survey(
    [
        family.poll.read(),
        activity,
        family.poll.vote(
            voter=current.agent.name,
            activity=activity.answer,
        ),
    ]
)

family.poll.read()

This is an explicit Survey step. Immediately before activity is rendered, the local execution host reads the newest committed view of this family’s poll. The read and its observed version are logged.

{{ shared_state.poll.votes }}

This is ordinary prompt templating. It uses the snapshot produced by the preceding read. Jinja formats a value already fetched; it does not itself fetch shared state.

activity.answer

While authoring, this is a serializable reference to the future answer of the question named activity. After that answer is validated, EDSL resolves the reference and constructs the write operation.

family.poll.vote(...)

This does not modify state while Python builds the Survey. It creates a write step containing the target, command, symbolic inputs, scope expression, and a stable step ID. The execution host applies it after the answer is committed.

Concurrency matters. A read observes a committed version at one moment. Another interview may write immediately afterward. EDSL records the exact version seen; it does not pretend that a prompt has a permanently current view. Writes are serialized and idempotent.

6. Run locally with Gemini

schedule = InterviewSchedule.grouped_round_robin("family_id", "turn")

results = (
    build_survey()
    .by(people)
    .by(Model("gemini-2.5-flash", service_name="google"))
    .run(
        cache=False,
        disable_remote_cache=True,
        disable_remote_inference=True,
        max_concurrency=5,
        interview_schedule=schedule,
        stop_on_exceptions=True,
    )
)

The chained .by(...) calls compose the Survey with agents and a model in the ordinary EDSL style. disable_remote_inference=True means EDSL orchestrates the run locally and calls Google directly using the local API key. It does not mean the Gemini model itself runs on the computer.

max_concurrency=5 limits resource use; it does not define experimental order. grouped_round_robin("family_id", "turn") does define order: interviews sharing a family are chained by their turn trait. Different families could still progress concurrently.

The first three votes were beach day, hike, and sailing. Sailing then took an early lead, and the remaining conformist personas joined it—even when sailing was not their assigned preference.

def tally(votes):
    return dict(Counter(votes.values()))

Each write stores the materialized state at that version. This makes analysis straightforward and robust to later machine-code changes: the Results artifact preserves what actually committed, not merely instructions for replay.

8. Complete runnable program

Save as shared_state_activity_poll.py. It is formatted and passes ruff check.

"""Local shared-state activity poll with heterogeneous participant preferences."""

from __future__ import annotations

from collections import Counter
import random

from edsl import (
    Agent,
    AgentList,
    InterviewSchedule,
    Model,
    QuestionMultipleChoice,
    Survey,
)
from edsl.sharedstate import (
    Command,
    Machine,
    SharedState,
    SharedStateMap,
    T,
    current,
    field,
    input_,
    put,
    reduce_,
    state_field,
)


ACTIVITIES = ("bike ride", "sailing", "hike", "beach day")
TRAITS_TEMPLATE = """You are a member of a group choosing a weekend activity.
Your preferred activity is {{ preferred_activity }}.
Your preference strength is {{ preference_strength }} on a 0-to-1 scale:
0 means you have no attachment to it; 1 means you feel extremely strongly.
Your conformity is {{ conformity }} on a 0-to-1 scale: 0 means you ignore what
other people chose; 1 means you strongly prefer joining the emerging consensus.
Vote as this person would, trading off personal preference against the votes you
can currently see. When there is no clear group preference, favor your own.
"""


def activity_poll() -> Machine:
    return Machine(
        name="ActivityPoll",
        constants={"activities": ACTIVITIES},
        fields={"votes": state_field(T.map(T.text(), T.choice(ACTIVITIES)), {})},
        commands={
            "vote": Command(
                inputs={
                    "voter": T.text(),
                    "activity": T.choice(ACTIVITIES),
                },
                effects=(put("votes", input_("voter"), input_("activity")),),
            )
        },
        view={
            "votes": field("votes"),
            "counts": reduce_("count_by", field("votes").values()),
        },
    )


def participants(n: int = 16, seed: int = 731) -> AgentList:
    rng = random.Random(seed)
    preferences = [ACTIVITIES[index % len(ACTIVITIES)] for index in range(n)]
    rng.shuffle(preferences)
    agents = []
    for index, preferred in enumerate(preferences):
        strength = rng.uniform(0.6, 0.9)
        conformity = rng.uniform(0.55, 0.9)
        agents.append(
            Agent(
                name=f"participant-{index + 1:03d}",
                traits={
                    "family_id": "weekend-group",
                    "turn": index,
                    "preferred_activity": preferred,
                    "preference_strength": round(strength, 2),
                    "conformity": round(conformity, 2),
                },
            )
        )
    return AgentList(agents, traits_presentation_template=TRAITS_TEMPLATE)


def build_survey() -> Survey:
    spaces = SharedStateMap(
        SharedState(poll=activity_poll()),
        state_id="weekend-activity-poll",
    )
    family = spaces.by(current.agent.family_id)
    activity = QuestionMultipleChoice(
        question_name="activity",
        question_text=(
            "Current votes are {{ shared_state.poll.votes }}. "
            "Which activity should the group choose?"
        ),
        question_options=list(ACTIVITIES),
    )
    return Survey(
        [
            family.poll.read(),
            activity,
            family.poll.vote(
                voter=current.agent.name,
                activity=activity.answer,
            ),
        ]
    )


def run(
    n: int = 16,
    seed: int = 731,
    model_name: str = "gemini-2.5-flash",
    max_concurrency: int = 5,
):
    people = participants(n=n, seed=seed)
    schedule = InterviewSchedule.grouped_round_robin("family_id", "turn")
    results = (
        build_survey()
        .by(people)
        .by(Model(model_name, service_name="google"))
        .run(
            cache=False,
            disable_remote_cache=True,
            disable_remote_inference=True,
            max_concurrency=max_concurrency,
            interview_schedule=schedule,
            stop_on_exceptions=True,
        )
    )
    answers = results.select("answer.activity").to_list()
    return results, Counter(answers)


if __name__ == "__main__":
    poll_results, counts = run()
    print(dict(sorted(counts.items())))
    events = poll_results.shared_state["bindings"][0]["events"]
    final_write = next(
        event for event in reversed(events) if event["kind"] == "write"
    )
    print(final_write["state"]["poll"]["votes"])
